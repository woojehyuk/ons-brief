### 2.1 조인 규칙

- 🔑 공통 키: `기지국ID` (형식 `XXX-0000`)
- 알람 → site_master: **1:1**, 매칭 225/225 ✅
- 알람 → 장비이력: **1:N**, 미매칭 71곳 ⚠️
  - **동일 `장비구분` 장비 우선** 연결
  - 동일 장비구분 없으면 → 기지국 전체 장비를 "참고"로 표시
- 알람 → 조치이력: **1:N** (`기지국ID` + `증상그룹`), 미매칭 44곳 ⚠️
- 미매칭은 오류 아님 → 카드에 "이력 없음" 표시 + 추정 경로(L2/L3)로 처리

### 2.2 데이터 품질 처리

- 🔴 **증상명 이기종 표기** → 정규화 사전 필수 (3장)
- 공백·대소문자 trim/upper 후 매칭
- 날짜 컬럼 → `datetime` 변환, 실패 시 null + 경고 로그
- `최근교체일` 결측 = 교체 이력 없음으로 해석
- 미해제 판단 = **`상태` 컬럼 기준** (`해제시각`은 보조, 결측이어도 상태 우선)

## 3. 증상 정규화 사전 (`symptom_map.csv`)

- 컬럼: `원본명, 증상그룹, 장비구분, 계열(HW/SW/LINK/POWER/ENV), 원격조치가능(Y/N)`

| 증상그룹 | 원본명 | 계열 | 원격조치 |
|---|---|---|---|
| OPT_RX_LOW | SFP Rx Power Low · SFP Receive Power Low · SFP RX OPTICAL POWER LOW | HW | N |
| OPT_MISSING | SFP Not Present · SFP Module Missing | HW | N |
| BATT_LOW | Battery Low Voltage · BATTERY UNDER VOLTAGE | POWER | N |
| VSWR_HIGH | RU VSWR High · VSWR Over Threshold · ANTENNA LINE VSWR MAJOR | HW | N |
| RU_TEMP | RU Temperature High · Radio Temperature Exceeded | ENV | N |
| RU_LINK | RU Link Down (CPRI) | HW | N |
| DU_SW | DU Software Abnormal Restart | SW | **Y** |
| DU_HW | DU Board Fail | HW | N |
| CLOCK_SYNC | DU Clock Sync Loss (GPS) | LINK | **Y** |
| RECT_FAIL | Rectifier Module Fail | POWER | N |
| BH_LINK | Backhaul Link Down | LINK | N |
| BH_CRC | Ethernet CRC Error | LINK | **Y** |

| AC_FAIL 🆕 | AC Mains Fail · EXTERNAL AC POWER FAILURE · Mains Failure | POWER | N |

- 🆕 v0.3: 실데이터 전수 확인 결과 알람명 39종 → 제조사별 표기 20종 추가, `AC_FAIL` 그룹 신설
  - 전체 매핑은 `symptom_map.csv`가 기준 (위 표는 대표 표기만)
- `BH_CRC`는 `BH_LINK`와 분리 (링크는 살아 있는 품질 저하라 원인·자재가 다름)
- 🔎 빌드 시 사전에 없는 알람명 발견 → **빌드 실패 + 목록 출력**
- 👤 이후 신규 알람명 추가 시 담당자 검수

## 4. 처리 로직

### 4.1 파이프라인

1. 로드 → 정규화 → 기지국 단위 집계
2. 조인 (site / 장비 / 조치)
3. 증상그룹별 원인 추론
4. 자재·주의사항 매핑
5. 분류·점수 → `briefing.json` → md 카드 + `briefing.html`

### 4.2 오늘 알람 요약 (기지국 단위)

- 알람 건수, 증상그룹 목록, 최고 등급 (Critical > Major > Minor > Warning)
- 미해제 건수, 최초 발생 / 최종 해제 시각
- 증상그룹별 당일 발생 횟수 (반복 발생 판단용)
- **다중 증상**: 증상그룹마다 원인 추론을 따로 실행
  - 카드 상단 = 대표 증상 1개 (최고 등급 → 동률 시 건수 많은 순)
  - 나머지 증상 = "추가 증상" 섹션에 각각의 원인 표시

### 4.3 원인 추론 (규칙 기반)

- 조회 기간: **조치이력 전체(1년)**, 최근 90일 건수는 별도 표시

| 단계 | 조건 | 결과 | 신뢰도 표시 |
|---|---|---|---|
| L1 | 동일 기지국 + 동일 증상그룹 이력 **≥1건** | 최빈 `실제원인` | 🟢 **확정근거** (n건 근거 명시, 1건이면 "1건 근거") |
| L2 | L1 없음 + 전국 동일 증상그룹 이력 **≥5건** + 최빈 원인 비율 **≥30%** | 전국 최빈 원인 | 🟡 **추정** (전국 통계, 비율 표시) |
| L3 | L2 조건 미충족 | 장비구분 기반 일반 원인 | 🔴 **추정** (근거 부족) |

- 동률 처리: **① 재발 Y 포함 원인 우선 → ② 최근 조치일 우선**
- 보조 신호 (원인 옆 태그)
  - 🔁 재발: 해당 이력 중 `재발여부=Y` 존재 → "이전 조치 효과 없음"
  - 🔧 펌웨어: 비고에 **최근 6개월 내**(2026-04-08 이후) 업그레이드 기록 + 장비구분 일치
  - 📈 고장多: 누적고장횟수 **≥3** (분포 확인 후 상위 10%로 조정 가능)
  - ⏳ 노후: 기준일 = **최근교체일, 없으면 설치일**, 기준일로부터 **8년 이상**
- **규칙**: 모든 원인 문장에 근거 ID(출처 파일·행·날짜) 1개 이상 연결, 없으면 반드시 "추정"

### 4.4 자재 · 주의사항 매핑 (`material_map.csv`)

| 실제원인 (예) | 챙길 자재 |
|---|---|
| 광 불량 / SFP 불량 | SFP 예비품, 광패치코드, 광파워미터, 클리너 |
| 커넥터 접촉불량 | 커넥터 세트, 압착공구, 방수테이프 |
| 차단기 트립 / 정류기 불량 | 차단기, 정류기 모듈, 멀티미터 |
| RU 하드웨어 불량 | RU 예비품(모델 일치), 토크렌치 |
| GPS 케이블 손상 | GPS 케이블·커넥터, 피뢰기 |

- **매핑에 없는 원인** → 장비구분별 기본세트 제공 + "추정" 표시

| 장비구분 | 기본세트 |
|---|---|
| RU | RU 예비품, VSWR 측정기, 커넥터 세트 |
| DU | DU 보드 예비품, 콘솔 케이블, 노트북 |
| 정류기 | 정류기 모듈, 멀티미터, 절연장갑 |
| 전송장비 | 이더넷/광 케이블, 테스터 |
| 광모듈 | SFP 예비품, 광파워미터, 클리너 |

- 주의사항 규칙
  - ⚠️ `고소작업여부=Y` → 안전벨트·안전모, 2인 1조, 기상 확인
  - 철탑·옥상 → 출입 승인 사전 확인
  - 정류기·배터리 → 전기 안전(절연장갑)

### 4.5 출동 분류

- 판정 순서: **🔴 > 🟡 > 🟢**, 상위 분류 조건을 하나라도 충족하면 상위 분류로 판정 (안전 측)

| 분류 | 조건 (OR) |
|---|---|
| 🔴 **지금 바로 출동** | 미해제 Critical · 미해제 Major 중 **HW/POWER 계열** · HW 원인 L1 + 재발 Y |
| 🟡 **원격 조치 먼저** | 원격조치가능 증상(Y) · 해제됐지만 Major 이상 · **당일 동일 증상그룹 ≥3회** (반복 발생·해제) |
| 🟢 **다음 정기점검 때** | 그 외 (해제 + Minor/Warning, 반복 없음) |

- 분류 사유 문자열을 카드에 표시 (예: "미해제 Critical 1건", "당일 반복 4회")
- 🔧 임계값은 모두 `config.yaml`로 외부화 (§6.1)

### 4.6 우선순위 점수 (순위 탭)

- `점수 = Σ등급가중(C4/M3/m2/W1) + 미해제건수×5 + min(과거 동일증상 건수, 10)×2 + 재발Y건수×3`
- 과거 동일증상 건수 상한 10 → 이력 많은 기지국이 순위를 독점하지 않도록
- 반복장애 순위: 조치이력 기준 기지국별 건수·재발률 Top 20

### 4.7 펌웨어 · 연식 비교 (분석 탭)

- 그룹: `제조사 + 모델 + 펌웨어`, `설치연도 구간(≤2015 / 2016–2020 / ≥2021)`
- 지표: 장비 수, 평균 누적고장, 오늘 알람 비율, 최빈 원인
- **n≥5 그룹만 비교** (n<5 그룹은 "표본 부족"으로 표시)
- 🔺 그룹 평균 대비 1.5배 이상 → "공통 원인 의심 (추정)" 표시

- 연락처 원본은 HTML에만 인라인, md·json에는 마스킹값만 저장

### 5.2 Markdown 카드

- 225장 **전부 생성** → `output/cards/{기지국ID}.md`
- `output/cards/index.md`: 분류순(🔴→🟡→🟢) → 점수 내림차순 정렬 목록
- 섹션 순서: 헤더 → 오늘 알람 → 대표 증상(이력·원인·근거) → 추가 증상 → 장비 → 자재 → 주의사항

### 5.3 HTML 앱 (`briefing.html`)

- 단일 파일, JSON 인라인, 오프라인 실행, 외부 의존 없음
- 배포: **로컬 파일만** (공유 링크 업로드 금지 — 담당자 연락처 포함)
- 탭: **카드 목록** · **반복장애 순위** · **펌웨어/연식 비교** · **데이터 품질**
- 기능: 지사/분류/등급 필터, 기지국 검색, 점수순 정렬, 카드 인쇄(A4 1장)
- 연락처: 기본 **마스킹** (`010-****-9279`), 카드별 토글로 전체 보기, 인쇄 시 마스킹 유지
- 모바일 폭 대응(현장 휴대폰 열람)
- 표시 규칙: "추정"은 노란 배지 + 점선 테두리로 확정과 시각 구분
