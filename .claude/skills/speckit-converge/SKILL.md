# converge — 한국어 실행 지침

실행 환경: `.specify/` 프로젝트 구조와 Bash/Python.

먼저 프로젝트 루트의 [공통 실행 규칙](../../../.specify/docs/workflow-common.md)을 읽는다.
사용자 입력은 `$ARGUMENTS`와 호출 메시지에서 확인한다. 본 작업 전 `hooks.before_converge`, 본 작업 후 `hooks.after_converge`을 공통 규칙에 따라 처리한다.

## 범위와 선행 조건

현재 `tasks.md`에 대해 `$speckit-implement`를 수행한 뒤 사용한다. 현재 코드와 `spec.md`·`plan.md`·`tasks.md`, 확정 원칙으로 의도를 판단하며 Git diff·브랜치 비교·과거 이력에 의존하지 않는다. 구현 실행 사실이 확인되지 않으면 이를 밝히고 먼저 구현하도록 안내한다.

유일한 쓰기는 `tasks.md` 끝에 새 단계를 추가하는 것이다. 기존 바이트·작업 순서·ID·체크 상태, 명세·계획·애플리케이션 코드는 변경하지 않는다. 훅도 이 범위를 따라야 한다.

## 절차

1. `.specify/scripts/bash/check-prerequisites.sh --json --paths-only`로 경로를 읽고 세 필수 문서의 존재를 별도로 확인한다. 누락 시 대응 스킬을 안내하고 부분 작업을 생성하지 않는다.
2. `FR-###`, 구현 가능한 `SC-###`, `USn/ACn`, 계획 결정과 확정 원칙으로 의도 목록을 만든다. 출시 후 사업 성과는 구현 의무와 분리한다.
3. 계획·작업의 경로와 관련 개념 검색을 통해 조사 범위를 정하고 실제 코드를 확인한다. 관련 없는 기존 코드를 명세에 없다는 이유로 제거 대상으로 만들지 않는다. 검토하지 못한 영역이나 실행 검증 부족은 명시한다.
4. 발견마다 안정적인 ID, 출처, 코드 위치·근거, 심각도와 유형을 기록한다.
   - `missing`: 필요한 구현이 없음.
   - `partial`: 일부만 충족.
   - `contradicts`: 명세·계획·필수 원칙과 충돌.
   - `unrequested`: 검토 범위 안의 추가 동작으로 정당성 확인이 필요함. 자동 삭제로 이어지지 않도록 검토 작업으로 표현한다.
5. 원칙의 필수 위반과 P1 핵심 기능 차단은 `CRITICAL`, 핵심 요구·인수 기준 누락은 `HIGH`, 부차적 미충족이나 정당성이 불명확한 추가는 `MEDIUM`, 경미한 미흡은 `LOW`로 분류한다.
6. 각 발견을 기존 미완료 작업의 출처·의도·대상 경로와 대조한다. 이미 해결하도록 작성된 작업이면 그 ID를 보고하고 중복 추가하지 않는다. 완료 표시된 작업에 실제 결함이 있으면 기존 표시를 바꾸지 않고 별도 보완 작업을 추가할 수 있다.
7. 추가 전 `ID | 유형 | 심각도 | 출처 | 근거 | 남은 작업/기존 ID` 표와 검사 범위를 간단히 보고한다. 최신 파일이 읽었던 내용과 달라졌으면 재확인하여 충돌을 피한다.
8. 새 보완 작업이 있을 때만 마지막에 `## Phase N: 수렴 보완 (Convergence)`를 추가한다. `N`은 기존 단계 최댓값+1, 작업은 기존 `T` 번호 최댓값+1부터 최소 3자리다. 원칙 위반을 먼저, 다음으로 심각도·의존성 순서로 쓴다. 각 줄에는 대상 경로, 출처, 유형, 완료 기준을 포함한다.

```text
- [ ] T042 [US1] src/example.py의 누락된 입력 검증 보완 (FR-003; partial; 완료 기준: US1/AC2 통과)
```

## 결과 구분

- `tasks_appended`: 새 작업 수와 단계, 다음 `$speckit-implement`를 보고한다.
- `pending_existing`: 해결할 차이가 기존 미완료 작업에 이미 포함됨. 파일을 그대로 두고 해당 ID를 보고한다. 수렴 완료라고 하지 않는다.
- `converged`: 확인 범위에서 실행 가능한 보완 사항이 없고 검증 부족으로 남겨 둔 판단도 없음. 파일을 바이트 단위로 유지하고 검사 범위와 근거를 보고한다.
- 평가 증거가 부족하면 미확인 항목을 보고하고 수렴을 단정하지 않는다. 새 작업이 없으면 빈 단계도 추가하지 않는다.
