# implement — 한국어 실행 지침

실행 환경: `.specify/` 프로젝트 구조와 Bash/Python.

먼저 프로젝트 루트의 [공통 실행 규칙](../../../.specify/docs/workflow-common.md)을 읽는다.
사용자 입력은 `$ARGUMENTS`와 호출 메시지에서 확인한다. 본 작업 전 `hooks.before_implement`, 본 작업 후 `hooks.after_implement`을 공통 규칙에 따라 처리한다.

## 절차

1. `.specify/scripts/bash/check-prerequisites.sh --json --require-spec --require-tasks --include-tasks`로 필수 문서를 확인한다. `spec.md`, `plan.md`, `tasks.md`와 확정 원칙을 읽고 관련 설계 문서만 추가로 읽는다.
2. `FEATURE_DIR/checklists/`의 점검표를 읽기 전용으로 집계한다. 표에는 전체·체크·미체크 수를 표시한다. 빈 점검표는 미검토로 구분한다. 미체크 항목의 의미를 확인하고, 동일 조건에서 이미 계속 진행하도록 승인받았다면 재질문하지 않는다. 실제 차단 조건이 남고 진행 지시가 없으면 해당 조건과 근거를 제시해 진행 여부를 확인한다. 이 스킬은 점검표를 임의로 통과 처리하지 않는다.
3. 실제 프로젝트 설정과 작업 범위를 확인한다. 새 생성물·로컬 비밀 파일 때문에 필요한 경우에만 ignore 규칙을 최소 수정한다. 기술 이름만으로 대규모 규칙을 생성하거나 lockfile, 공유 IDE 설정, `.env.example`을 무조건 제외하지 않는다.
4. 작업 ID, 상태, 의존성, `[P]`, 파일을 읽고 미완료 작업을 실행한다. 완료 작업은 재실행할 이유가 있는지 먼저 확인한다. 같은 파일이나 공유 자원을 건드리는 작업은 순차 처리한다. 병렬 표시는 허용된 실행 범위에서만 사용한다.
5. 사용자·명세·원칙이 요구한 테스트와 변경에 적절한 검증을 수행한다. TDD 요구가 있으면 테스트 실패 → 구현 → 통과 순서를 따른다. 의미 없는 테스트로 구현 문구만 확인하지 않는다.
6. 실패를 진단·수정하고 의존하는 작업은 멈춘다. 영향을 받지 않는 작업은 진행할 수 있다. 원인을 해결할 수 없으면 막힌 작업, 원인, 필요한 조치를 보고한다. 실패한 검사를 성공으로 표기하지 않는다.
7. 실제 작업과 해당 검증이 끝났을 때만 `tasks.md`의 해당 체크박스를 `[X]`로 바꾼다. ID·설명·다른 작업 상태를 보존한다. 주요 진행과 차단 요인을 사용자에게 알린다.
8. 요청 범위의 구현을 명세·계획·인수 기준과 대조하고 필수 테스트/빌드/정적 검사 및 quickstart 검증을 수행한다. 실제 요구된 커버리지 기준이 있을 때 적용한다. 요청받지 않은 배포나 게시를 완료 조건에 추가하지 않는다.

## 완료 보고

완료·남은·차단 작업과 바뀐 동작, 실행한 검증 및 결과, 미실행 검증의 사유를 보고한다. 필수 작업이나 검증이 남으면 전체 완료로 보고하지 않는다. 필요하면 `$speckit-converge`로 구현 누락을 확인한다.
