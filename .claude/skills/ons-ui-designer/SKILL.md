# ONS UI Designer

사내 업무 도구 화면을 DESIGN.md 규칙대로 **계획 제안 → 승인 → 구현 → 자체 점검** 순서로 만드는 스킬.
사용자는 비 IT 직군으로 가정. 낯선 용어는 짧게 풀어 쓰고, 답변은 개조식·명사형 종결.

## 작업 순서

### 1. 규칙 확인
- 스킬 폴더의 `DESIGN.md` 읽기. 색·글꼴·레이아웃·컴포넌트 규칙의 원본
- 시작 틀: `assets/ons-base.css`(디자인 토큰 + 공통 컴포넌트), `assets/template.html`(상단 바 + 카드 + 표 기본 화면)
  - DESIGN.md와 다르면 DESIGN.md 우선

### 2. 데이터 파악 (데이터 파일이 있을 때)
- 건수, 열 이름, 열별 고유값, 기간, 빈칸 확인
- 이상값 찾기: 같은 뜻 다른 표기(예: "OK"/"양호"), 빈칸, 형식 불일치
- 엑셀 한글이 콘솔에서 깨지면 UTF-8 파일로 저장 후 읽기
- 이유: 데이터 문제를 모른 채 만들면 숫자가 틀린 대시보드가 됨

### 3. 디자인 계획 제안 (구현 전 필수)
아래 틀로 제안하고 승인 대기. 코드는 아직 작성하지 않음.

```
## 📊 데이터 요약        (데이터가 있을 때) 핵심 숫자 3~5줄
## ⚠️ 정해야 할 데이터 문제  표: 항목 | 상황 | 추천 처리
## 🧭 화면 구성          위→아래 순서 목록 (상단 바 → 필터 → 요약 카드 → 차트/본문 → 표)
## 🛠️ 만드는 방식        파일 형태, 저장 위치, BE 필요 여부, 오프라인 제약
## ❓ 승인 요청          바꿀 부분 질문 + 꼭 정해야 할 항목
```

- 화면 1개 → 상단 바만. 화면 2개 이상 → 상단 바 + 왼쪽 Navigation Rail
- 요청과 DESIGN.md가 충돌하면(예: "빨간 배경으로", "그라데이션") 계획에 ⚠️로 밝히고 사용자가 선택하게 함
- 모호한 값은 추천값을 함께 제시

### 4. 구현 (승인 후)
- "나만 볼 HTML", 목업, 단순 대시보드 → **단일 HTML 파일**(데이터 내장, 서버 없음). BE가 필요 없다는 점 안내
- 여러 화면·저장 기능이 필요한 앱 → AGENTS.md 기술 스택(Vite + React + TS) 사용
- 저장 위치: 산출물 `project/output/`, 앱 소스 `project/frontend/`
- 차트가 있으면 `dataviz` 스킬도 참고하되 색은 DESIGN.md 토큰 우선
- 예시·샘플 데이터는 가상 값만("가나국사", "RU-0001")

### 5. 자체 점검 → 보고
아래 체크리스트를 확인한 뒤, 파일 위치·여는 방법·남은 제약을 개조식으로 보고.

## 체크리스트
- [ ] 색은 CSS 변수(토큰)만 사용, 넓은 면에 진한 SK 레드 없음
- [ ] 상단 바 56px 파스텔 레드, "SK ONS" + 화면 제목, 가로 메뉴 없음
- [ ] Primary 버튼 화면당 1개 이하
- [ ] Pretendard 글꼴, 숫자 `tabular-nums` + 표에서 오른쪽 정렬
- [ ] 천 단위 쉼표, 숫자와 단위 사이 한 칸(`1,200 원`), 날짜 `YYYY-MM-DD`
- [ ] 상태 표시는 배지 + 글자(정상/주의/위험), 색만으로 구분하지 않음
- [ ] 표: 가로선만, 행 높이 44px 이상, 빈 데이터면 빈 상태 문구
- [ ] 애니메이션 600ms 이하, `prefers-reduced-motion` 대응, 무한 반복 없음
- [ ] 768px 이하에서 한 열로 접힘, 표는 가로 스크롤
- [ ] 이모지 아이콘 없음(선 아이콘 SVG만), 그라데이션·큰 그림자 없음
- [ ] 키보드 이동 가능, 포커스 테두리 보임
- [ ] 가능하면 브라우저로 열어 콘솔 오류 확인 후 테스트 프로세스 종료
