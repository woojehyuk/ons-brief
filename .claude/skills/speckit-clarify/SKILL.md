# clarify — 한국어 실행 지침

실행 환경: `.specify/` 프로젝트 구조와 Bash/Python.

먼저 프로젝트 루트의 [공통 실행 규칙](../../../.specify/docs/workflow-common.md)을 읽는다.
사용자 입력은 `$ARGUMENTS`와 호출 메시지에서 확인한다. 본 작업 전 `hooks.before_clarify`, 본 작업 후 `hooks.after_clarify`을 공통 규칙에 따라 처리한다.

## 절차

1. `check-prerequisites.sh --json --paths-only`로 `FEATURE_DIR`, `FEATURE_SPEC`을 읽는다. 명세가 없으면 `$speckit-specify`를 안내한다. 경로 오류를 브랜치 이름 변경으로 우회하지 않는다.
2. 명세와 확정된 프로젝트 원칙을 읽고 아래 범주의 상태를 명확/부분/누락/해당 없음으로 내부 분류한다.
   - 기능 목표·범위·사용자 역할, 개체·식별·상태 전이·규모.
   - 사용자 흐름·오류/빈 화면/로딩·접근성·언어.
   - 성능·가용성·복구·관측성·보안/개인정보·해당 규정.
   - 외부 연동·실패·포맷/버전, 경계·동시성·충돌.
   - 제약·절충, 용어 일관성, 인수 기준·완료 조건, 미해결 자리표시자.
3. 구현·검증에 영향을 주는 질문을 영향도와 불확실성 순으로 최대 5개 선정한다. 이미 답한 질문, 사소한 표현, 계획에서 결정할 기술 선택은 제외한다. 숫자는 할당량이 아니라 상한이다.
4. 한 번에 하나씩 묻는다. 질문은 배경 문서를 몰라도 답할 수 있는 완전한 문장으로 쓰고, 왜 필요한지와 추천안의 근거를 짧게 설명한다. 의미가 분명한 선택지나 자유로운 짧은 답변을 허용한다. 한국어 답변에 영문 기준의 단어 수 제한을 적용하지 않는다.
5. 답변이 수락될 때마다 `## 명확화 (Clarifications)` 아래 `### Session YYYY-MM-DD`에 `- Q: 질문 → A: 답변`을 하나씩 기록하고 관련 요구사항·시나리오·성공 기준도 즉시 갱신한다. 기존 `## Clarifications`가 있으면 재사용한다. 모순된 이전 문장을 대체하고 다른 섹션의 순서를 보존한다. 매 답변 뒤 변경 충돌을 확인하여 안전하게 저장한다.
6. 중요한 모호성이 해소되거나 사용자가 중단·진행을 요청하거나 5개를 물었으면 질문을 끝낸다. 시간 경과를 답변으로 보지 않는다. 남은 중요 항목은 보류 사유와 영향으로 보고한다.
7. 중복 Q/A, 남은 모순, 해결한 질문의 자리표시자, 용어 불일치를 확인한다. 질문이 없거나 사용자가 중단했다는 이유만으로 모든 범주를 명확으로 표시하지 않는다.
8. `checklists/requirements.md`가 있으면 갱신된 명세로 재평가한다. 코드 펜스 밖의 체크박스만 대상으로 실제 판정이 바뀐 `[ ]`/`[x]` 부분만 수정한다. 그 외 문구·순서·공백·기존 `[X]` 대소문자는 유지한다. 사용자 정의 점검표는 수정하지 않는다.

## 완료 보고

질문·답변 수, 명세 경로와 바뀐 섹션, 범주별 해결/보류/기존 명확/남은 문제, 점검표의 전후 통과 수·신규 통과·회귀·미체크 항목을 요약한다. 중요한 미결정에 따라 `$speckit-plan` 진행 가능 여부를 설명한다.
